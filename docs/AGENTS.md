# docs/ — Codex Guide

## Directory purpose
- Static site assets for the published ASI Letter page. `index.html` renders the site; `letter.md` mirrors the latest signed Markdown release.

## Key workflows/commands
- `python3 scripts/sync_docs_with_latest.py [--check]` — copies newest `letter/ASI-Letter-v*.md` into `docs/letter.md`.
- `python3 scripts/update_version_metadata.py [--check] [targets...]` — refreshes release markers (title/data attributes/comment) in `index.html`.

## File map (every tracked item)
| filename | what it does | important invariants / gotchas | how it’s used |
| --- | --- | --- | --- |
| `AGENTS.md` | This directory guide. | Keep aligned with site asset roles; defer to root policy. | Contributor reference. |
| `index.html` | Static HTML for the public site with release-version markers, CTA links, styling, and pre-rendered letter content. | Markers (`<!-- release-version -->`, `data-release-version`, title) must match latest release; `update_version_metadata.py` rewrites them. Render markers are updated by `render_index_html.py`. The schema.org JSON-LD between `structured-data` markers is regenerated by `update_version_metadata.py`; Open Graph/Twitter tags are static and version-free. Heading `id`s and Table of Contents links are derived from the letter text on every build by `render_index_html.py` -- never stored, so sections can be added, removed, reordered or reworded freely; a TOC entry matching no heading fails the build. Footer status is updated by OTS workflows. Avoid manual drift from automation expectations. | Served as site entrypoint; updated by release/OTS workflows, metadata, and rendering scripts. |
| `letter.md` | Markdown copy of the latest signed letter. | Generated/overwritten by `sync_docs_with_latest.py`; keep consistent with `letter/` sources. | Displayed on site; checked by release pipeline for freshness. |
| `letter.md.asc` | Clear-signed copy of the latest release, under a stable name. | Generated by `publish_latest_artifacts.py`; byte-identical to its `letter/` source and must hash to the `sha256` in `RELEASES.json`. Marked `-text` in `.gitattributes`. | Lets anyone verify the letter using only files served from the site. |
| `letter.md.asc.ots` | OpenTimestamps proof for the signature above. | Generated by `publish_latest_artifacts.py`; binary, marked `-text`. | Bitcoin-anchored proof of when the signature existed. |
| `alice-asi-publickey.asc` | Author public key. | Generated from `keys/alice-asi-publickey.asc`; never edit here. | Imported by verifiers who only have the website. |
| `FINGERPRINT.txt` | Author key fingerprint. | Generated from `keys/FINGERPRINT`; 40 uppercase hex, no spaces. | Trust anchor to check an imported key against. |
| `releases.json` | Machine-readable release manifest. | Generated from `letter/RELEASES.json`; never edit here. | Lets agents enumerate releases and check hashes. |
| `sitemap.xml` | Sitemap for all published URLs. | Generated by `gen_discovery.py`; do not hand-edit (it had drifted eight releases stale). | Crawler discovery; referenced by `robots.txt`. |
| `llms.txt` | Structured index for automated readers. | Generated by `gen_discovery.py` from the same URL table as the sitemap. | Tells agents what the letter is, which file is authoritative, and how to verify it. |
| `.nojekyll` | Disables Jekyll processing on GitHub Pages. | Must exist; without it Pages drops paths beginning with `.` or `_`. | Ensures `docs/` is served verbatim. |
| `<key>.txt` | IndexNow ownership credential. | Filename without `.txt` MUST equal the file's contents; `ping_indexnow.py` locates it by that property. Public by design, not a secret. Keep it out of the sitemap. | Proves site ownership when announcing updated URLs. |
| `overview.html` | ~700-word explainer. | Carries its own canonical, description, social tags and `WebPage` JSON-LD declaring it is *about* the letter rather than a copy of it, so the two pages reinforce one canonical work instead of competing. | Entry point for readers who want the short version. |

## Codex operating guidance
- Edit policy: Avoid manual edits to generated `letter.md` or release markers in `index.html`; layout/content changes should respect placeholders used by automation.
- Validation: Run `python3 scripts/sync_docs_with_latest.py --check` to detect stale Markdown and `python3 scripts/update_version_metadata.py --check` to confirm version markers.
- Common failure modes: stale version markers after new manifest, editing `letter.md` directly, or altering HTML in ways that break release/OTS automation.
